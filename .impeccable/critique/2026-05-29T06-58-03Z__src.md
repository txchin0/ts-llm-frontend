## Anti-Patterns Verdict

**LLM assessment:** This does not read as a generic ChatGPT clone. Ember has a deliberate voice (Fraunces wordmark, ember accent, open assistant transcript, distinct thinking/tools). The remaining AI tells are smaller: uppercase tracked "AGENT" speaker label, markdown blockquote side-stripe, and header backdrop blur (glassmorphism used as atmosphere). Overall aesthetic is warm and competent, not purple-gradient slop.

**Deterministic scan (CLI on `src`):**
- `side-tab` warning: `src/components/markdown.css:63` — `border-inline-start: 3px solid` on blockquotes
- `em-dash-overuse` and `numbered-section-markers` on `tokens.css`: **false positives** (OKLCH comment syntax, not body copy)

**Browser overlay (injection succeeded):** One live finding: **positioned child clipped by overflow container** (likely sticky header/composer inside `.app { overflow: hidden }`). Overlays were visible in the critique browser tab during the run.

## Overall Impression

Ember already feels like a real product surface, not a template. The biggest gap is **recognition**: a technical owner will use it daily, but the header asks them to memorize icons and API field names. Plain-language identity and one visible status affordance would lift trust without adding chrome.

## What's Working

1. **Conversation hierarchy** — User bubbles vs open assistant prose, collapsible thinking, and tool chips match PRODUCT.md's "show the work honestly."
2. **Composer ergonomics** — Sticky bottom bar, safe-area padding, auto-grow textarea, streaming stop/send swap, and mobile-hiding of desktop hints.
3. **Trust copy** — "Conversations are never saved" and identity-switch warning align with the privacy story.

## Priority Issues

**[P1] Icon-only header toolbar**
- **Why:** Brain, theme, and new-chat are icon-only with tooltip-only names. Jordan cannot infer purpose; Sam gets no persistent text label.
- **Fix:** Add visible text on at least theme + new chat at `min-width`, or a compact overflow menu with labels. Keep icons + `aria-label`.
- **Suggested command:** `/impeccable clarify` (labels) + `/impeccable adapt` (responsive header)

**[P1] Identity dialog speaks API, not user**
- **Why:** Label `user_id`, description cites `user_id` with every request. Breaks "plain and direct" brand for anyone not reading server docs.
- **Fix:** Label "Speaking as", helper text about server-side identity, placeholder "e.g. thomas-home". Keep monospace styling on the value only.
- **Suggested command:** `/impeccable clarify`

**[P2] Markdown blockquote uses side-stripe accent**
- **Why:** Matches impeccable's side-tab antipattern tell; assistant blockquotes will look "AI scaffold" in long replies.
- **Fix:** Full border or inset background tint using `--surface-2`, no thick inline-start stripe.
- **Suggested command:** `/impeccable quieter`

**[P2] Overflow clipping in app shell**
- **Why:** Browser detector flagged clipped positioned children; `.app { overflow: hidden }` can trap popovers/tooltips near header/composer edges.
- **Fix:** Audit sticky layers; clip only the transcript scroll region, not the whole shell. Prefer native `<dialog>`/popover (already used for identity).
- **Suggested command:** `/impeccable audit`

**[P2] Mobile hides who you're speaking as**
- **Why:** Below 560px, `userId` and `session active` hide; only a user icon remains. Casey cannot confirm identity mid-flow without opening the dialog.
- **Fix:** Keep a truncated mono pill or initials badge visible on small screens.
- **Suggested command:** `/impeccable adapt`

## Persona Red Flags

**Alex (Power User):** No keyboard shortcut for new chat or stop (only Enter send). Theme cycles through three states with no menu; must click repeatedly. New chat disabled until session exists (correct) but offers no "clear input" shortcut.

**Casey (Mobile):** Primary actions (send, mic) are correctly bottom-aligned. Identity and session status vanish on narrow viewports. Dialog is usable, but confirming `web-user` requires an extra tap. State is in-memory only (by design); returning after interruption loses the thread.

**Sam (Accessibility):** Icon buttons have `aria-label` (good). "AGENT" label uses uppercase + letter-spacing (harder to read for some users). Error blocks pair color with icon (good) but also expose raw `error.code`. Theme toggle state is only in the accessible name, not visible text.

**Technical owner (project):** Empty state does not mention that the agent server must be running or how to configure the proxy. First failure may feel like a broken UI rather than setup.

## Minor Observations

- Header `backdrop-filter` is decorative glass; DESIGN.md says blur should be rare.
- `AGENT` speaker row is a small uppercase kicker; consider sentence case "Agent" with the ember dot only.
- Token usage footer is useful for power users but adds visual noise; could collapse behind a "details" control.
- Empty-state `rise` animation is gated by global reduced-motion (good).
